- Multi-tenancy: data is scoped by organizations → brands; new brand-scoped tables carry organization_id (auto-filled from brand_id by trigger) and use is_org_member/has_org_role in RLS. Why: strict tenant isolation without breaking legacy brand_id-based tables.
- Brand Brain is the single source of truth for AI; only confirmed data is used and website scan results stay draft until the user confirms. Why: AI must never invent business facts.
- Dashboard layout renders <Outlet />; home lives in dashboard.index.tsx. Why: avoid pathname-gated layouts.
- Design tokens are light-first with html.dark for dark mode; legacy glass utilities map to clean cards. Why: one coherent design system across old and new screens.
- Publishing goes only through publishing_jobs (one idempotent job per post+target, processed by src/lib/publishing-queue.server.ts with retry/backoff); generated_posts.status is derived from jobs. Why: no double publishing, real per-target state.
- AI content generation builds facts only from confirmed Brand Brain data via src/lib/brand-context.server.ts. Why: one shared, non-hallucinating context for all generators.
- Inbox: Meta events enter only via /api/public/webhooks/meta (HMAC-verified, deduped in webhook_events) and become conversations/messages; AI only creates ai_reply_drafts (src/lib/inbox-agent.server.ts) and sending always requires a human action. Why: no unreviewed messages to customers until auto-send is explicitly built.
- Observability lives in src/lib/observability.server.ts: logAiUsage/logError (best-effort, never throw), AI daily limits per plan, and fireBrandWebhooks (HMAC-signed outbound CRM events). Why: one place for cost tracking, error tracking, and external integrations.
- Publishing queue recovers jobs stuck in "processing" >10 min back to pending at each run; retryFailedJobs resets failed jobs. Why: a crashed worker must never strand a scheduled post.
- pg_cron jobs call /api/public/cron/* with the apikey header; new cron endpoints must be registered in pg_cron the same way. Why: cron routes are public-prefix and rely on that header on the published URL.
- AI Team (Echipa AI): bot definitions live in src/lib/ai-team.ts (shared client/server, incl. plan gating botAllowed); chat runs via src/lib/ai-team.functions.ts using confirmed Brand Brain context, daily AI limit and usage logging. Why: one place to add/adjust bots, gating enforced server-side.
- Browser subtitle and Studio history utilities use SSR-safe modules with browser APIs only inside functions called after hydration; never name SSR-reachable modules `*.client.*`. Why: the production import guard rejects that filename even when dev rendering succeeds.
